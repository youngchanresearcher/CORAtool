New submission.

CORAtool implements Combinational Regularity Analysis (CORA), a
configurational comparative method. It is named CORAtool rather than CORA
because package names are compared without regard to case and a package
named 'cora' is already on CRAN.

Derivative work and licensing. The algorithms are ported from the Python
packages CORA and LOGIGRAM (Sebechlebska, Mkrtchyan and Thiem,
doi:10.21105/joss.05019), which are distributed under GPL-3. CORAtool is
released under GPL (>= 3). The three original authors are listed in
Authors@R as copyright holders, and inst/NOTICE records what derives from
where, including the Petrick solver. The four bundled data sets are the
example data shipped with the Python package under the same licence. The R
code is an independent implementation rather than a translation of any
source file, and the package is not endorsed by the original authors, which
the Description states.

Two examples use \dontrun{}: cora_python_available() and
cora_compare_python(). Both can start Python through 'reticulate', and on a
machine with no interpreter configured recent versions of 'reticulate'
provision one at that moment, which cost 28 seconds of elapsed time and a
network round trip when the examples were run normally. 'reticulate' is a
Suggests used only for an optional cross-check against the reference
implementation; nothing else in the package needs Python, and the package
checks and tests fully without it.

If the Description raises a spelling NOTE, the words flagged are author
surnames (Sebechlebska, Mkrtchyan, Thiem), named algorithms
(Quine-McCluskey, McCluskey, Petrick) and terms of art in this literature
(INUS, conjunctivity, disjunctivity). All are spelled as intended.

Checked with R CMD check --as-cran, no ERRORs and no WARNINGs, on Windows 11
with R 4.6.1 and on Ubuntu 24.04 with R 4.3.3.
